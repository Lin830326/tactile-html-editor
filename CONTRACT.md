# Tactile HTML editor — module contract

Tactile is a browser-based visual editor for **existing HTML files** (typically AI-generated reports, slide
decks, landing pages). It aims to feel like PowerPoint / Word: click to select, double-click to type, drag to
reorder, resize with handles, right-click for row/column operations — plus an AI agent that edits the page
through the same operations. UI languages: **Traditional Chinese (zh-TW)**, Simplified Chinese (zh-CN) and English (see "Interface language"). No build tools, no frameworks, no
external JS libraries: plain ES2020 classic scripts that share the global `window.HE`.

It ships two ways from the same sources:
1. `dist/tactile.html` — one self-contained file the user double-clicks (file://, offline, Chrome/Edge/Firefox/Safari).
2. A claude.ai Artifact (sandboxed iframe, CSP: no network except CDN scripts; `alert/confirm/prompt` are
   blocked; `<a download>` is blocked — use the `downloads` capability; Claude is reachable via the `sample`
   capability). Detect with `HE.env.inArtifact`.

Match core.js style: 2-space indent, single quotes, semicolons, short comments only where the why isn't obvious.

## The two DOMs (most important rule)

- **Model** `HE.doc.model` — a `DOMParser` Document: the clean source of truth; scripts never run; this is what
  gets exported. Every element carries `data-he-id` (`HE.ID_ATTR`), except descendants of `<svg>`/`<math>`.
- **Live** `HE.live.doc` — the canvas's edit frame, rendered from the model. It is always same-origin and runs no
  page script, except in compat mode (see "Page scripts and trust"). The same element has the same `data-he-id`
  in both. The run frame that previews a scripted page is **not** the live doc: it is cross-origin, has no ids,
  and nothing reads from it or writes to it; the editor only hears fixed messages from it (its wrapper's
  navigation report and the two of the page's drag guard).
- **Never mutate either DOM directly for a user-visible edit. Always go through `HE.ops.*`** (they change both
  and record undo). The only exceptions: canvas.js puts `contenteditable` on a live element during in-place
  text editing and commits with `HE.ops.commitLiveContent(id)`; and purely visual editor-only state on live
  nodes (e.g. layers' "hide in editor") that is never committed. Editor-only live attributes must be in the
  set core strips: `contenteditable`, `spellcheck`, `data-he-editing`, `data-he-hidden`, `data-he-fx-demo`.
  Editor chrome around the frames (`.cv-run`, `.cv-run-shield`, the `is-running` class on `.cv-frame-box`) lives
  in the editor document, never in either DOM.
  Editor-only live nodes carry `data-he-editor` (e.g. `<style data-he-editor="fx-demo">`) and are never committed.
  `data-he-style` (the managed head styles) is the only `data-he-*` attribute an export keeps.
- Read element info for display from the model (`HE.doc.byId(id)`) and computed styles from live
  (`HE.live.byId(id)` + `HE.live.doc.defaultView.getComputedStyle(el)`).
- Map a live node to its id with `HE.live.idOf(node)` (nearest identified ancestor).

## Core API (see core.js for exact behaviour)

Events — `HE.on(evt, fn)` returns an unsubscribe fn; `HE.emit(evt, data)`:
| event | payload | meaning |
|---|---|---|
| `doc:loaded` | `{name}` | a new document replaced the old one (history reset) |
| `doc:replaced` | `{history?}` | `replaceDocument` swapped the whole page (one undo step; the canvas ends compat mode); also emitted, with `history: true`, by an undo or redo of that step |
| `doc:render` | `{reason:'load'|'restore'|'op'}` | canvas must re-render the iframe from the model |
| `doc:changed` | `{label, history?}` | model changed (after every committed transaction, undo, redo) |
| `doc:named` | `{name}` | file name changed |
| `canvas:ready` | `{doc}` | iframe rendered; `HE.live.doc` is valid (fires after every render) |
| `selection:changed` | `{ids}` | selection changed |
| `hover:changed` | `{id}` | canvas hover target (id or null) |
| `mode:changed` | `{mode:'edit'|'preview'}` | |
| `history:changed` | `{canUndo, canRedo, undoLabel, redoLabel}` | |
| `history:before` | — | about to undo/redo (canvas commits any text edit) |
| `textedit:start` / `textedit:end` | `{id}`; at the end also `{changed, caret}` | in-place text editing state. `caret`: how many characters of the element's text came before the caret when a committed edit ended, or null (HE.prov puts the next citation there) |
| `tab:changed` | `{group, name}` | panel tab switched |
| `settings:changed` | `{key, value}` | |
| `ai:busy` | `{busy}` | the agent is running (others may disable editing) |
| `doc:trusted` | `{trusted}` | the document's scripts were allowed or stopped (the canvas updates its frames: it re-renders the edit frame, and emits `canvas:ready`, only when the compat sandbox changes; otherwise it adds or removes the run frame) |
| `live:headstyle` | `{key, el}` | `setHeadStyle` created a managed `<style>` in the live doc (not on a full re-render) |
| `fx:demo` | `{running}` | an effect demo started or stopped (canvas redraws the overlay every frame while it runs) |
| `print:ready` | `{frame, deck}` | 匯出 PDF: the print frame has loaded and its `print()` is called next (`deck`: its boards print one per page) |

`HE.doc`: `model, name, trusted, load(html,{name, trusted}), setTrusted(v), hasScripts(), setName(n),
serialize({keepIds, mark}), snapshot(), byId(id), idOf(el), html(id,{keepIds}), outline({maxLines, rootId}), body,
head, isRoot(el), newId(), ensureIds(root), dedupeIds(root, allowedSet), repairIds(root), idsIn(el)`.
In the model a head `<noscript>` is stored as `<template data-he-noscript>`; `serialize()`/`html()` without
`keepIds` turn it back into `<noscript>`. `serialize({mark: {ids, attr}})` sets `attr` on the copies of those
elements (the canvas's run frame marks the layers hidden in the editor); an export never passes it.

`HE.live`: `doc, byId(id), find(id), idOf(node), import(node), safe(), clean(root)`. `safe()` is false only while the
edit frame still runs scripts although compat mode has ended (trust dropped, the user turned it off, or an undo
brought back script it was not confirmed over) and the scriptless re-render is loading; `byId` then
returns null, so ops fall back to a re-render instead of copying into that frame. `find(id)` skips that check:
use it only to read the frame (committing typed text). `clean(root)` removes from a copy taken out of the live
frame (or from a live element whose frame runs no page script) every piece of script the model does not already have (`util.stripScript` against `scriptBits(model)`),
toasts (at most every 2 s) when it removed something, and returns the count. Every live-to-model path calls it.

`HE.PAGE_SANDBOX` — the sandbox flags of a frame that runs the page's own scripts (the canvas run frame, 在新分頁預覽):
`allow-scripts allow-forms allow-modals allow-popups`. Never add `allow-same-origin` to it. It is read-only
(non-writable, non-configurable), and canvas.js and fileio.js copy it into a closure constant when they load, so a
compat-mode page that reaches `window.HE` cannot widen the frames built after it.

`HE.ops` (every op works inside or outside a transaction; outside, it records its own undo step;
`opts.label` names the undo step; `opts.coalesce` = string key: consecutive same-key ops within 1.2 s merge into
one undo step — use it for sliders, drags, typing in numeric inputs):
- `setStyle(ids, {prop: value}, opts)` — '' or null removes; supports `'x !important'`; kebab or camel.
- `setAttr(ids, {name: value|null}, opts)`; `setClasses(id, 'a b c', opts)`
- `setText(id, text)`, `setInnerHTML(id, html)`
- `replaceHTML(id, html) → newTopIds[]` (body/head/html handled; ids from the old subtree may be reused)
- `insertHTML(refId|null, 'before'|'after'|'prepend'|'append', html) → newTopIds[]` (null ref = body)
- `remove(ids)`, `move(id, refId, position)`, `nudge(id, -1|+1)` (skips script/style/… siblings; false and no
  undo step when nothing visible to swap with), `visualSibling(elOrId, -1|+1)`, `duplicate(ids) → newIds[]`
  (a copied id that something inside the copy refers to gets a free name, `email` → `email-2`, with its
  label/aria/#anchor references; other ids stay so `#id` CSS still styles the copy)
- `levelTarget(elOrId, -1|+1, skipIds?, tookIds?) → {refId, position} | null` and
  `changeLevel(ids, -1|+1) → movedIds[]`: -1 moves an element out to sit right after its parent, +1 moves it in
  as the last child of the nearest visible sibling above (never into one in `skipIds`; `changeLevel` skips the
  selected ones, ignores roots, and lets later elements follow into a container an earlier one just entered).
  Placements must pass `util.keepsChild` (and `util.acceptsDrop` for a fresh container); one undo step, none
  when nothing can move. contextmenu.js uses it for its menu items and `alt+shift+left`/`alt+shift+right`.
- `insertHTML`/`replaceHTML`/`setInnerHTML`/`setText`/`setAttr`/`replaceDocument` stop a trusted document's
  scripts when they add script the page does not already have (see "Page scripts and trust")
- Text written into `<style>`/`<script>`/`<iframe>`… (`setText`, `setHeadStyle`, `insertHTML`/`setInnerHTML` into
  one) is stored as text with `</tag` escaped to `<\/tag`, so it cannot end the element on the next parse
- `wrap(ids, tag, attrs) → wrapperId`, `unwrap(id)`
- `mutate(id, fn(modelEl, modelDoc), opts)` — free-form model edit of a subtree, then live copy refreshed
  from model (use for table row/column ops etc.). Cloned nodes keep duplicate ids until repaired — core
  repairs them after fn.
- `commitLiveContent(id)` — after contenteditable editing. It reads the live element (`find`), strips the
  editor-only attributes and `live.clean`s it: the live element itself when its frame runs no page script (so the
  canvas keeps matching the model and the next commit does not strip and toast again), otherwise only the copy
  (a compat-mode frame keeps what page scripts did to it), then commits
  only if the result differs from the model. The canvas calls it only when the user really changed the text
  (a trusted `input` event, or an editor command such as bold, link or line break), so a compat-mode page
  script that rewrites the element during editing does not reach the model on its own.
- `replaceDocument(html)`, `setHeadStyle(key, css)`, `getHeadStyle(key)`, `setTitle(text)`. Head style keys
  (`<style data-he-style="key">`, exported as is): `custom` (inspector page CSS), `ai` (set_page_css), `fx` and
  `fx-motion` (owned by HE.fx: regenerated from the `tfx-*` classes, never edit them elsewhere), `pages` (owned by
  HE.pages: regenerated from the pages of a multi-page document), `island` (owned by HE.island: written while the
  document holds a floating island)
Group several ops into one undo step: `HE.history.transact(label, () => {...})` or
`await HE.history.transactAsync(label, async () => {...})`.

`HE.history`: `undo(), redo(), canUndo(), canRedo(), transact(label, fn, opts), transactAsync(...), begin(label, opts), end(), active,
top()` (newest entry; an entry keeps its identity as it moves between the undo and redo stacks), `flushRender()`,
`addCloser(fn(tx))` — fn runs when the outermost transaction is about to close; ops it calls join that undo step
(it runs once per transaction, not for undo/redo/load, which open none). HE.fx uses it to keep its CSS in step.
Each entry records whether its saved state was trusted: undoing to a trusted state trusts the document again,
and redoing into a state with script the user has not allowed stops the scripts. An entry made by
`replaceDocument` is marked `replaced`: stepping over it emits `doc:replaced` with `{history: true}`.

`HE.sel`: `ids, primary, set(ids,{silent}), add(id), toggle(id), clear(), has(id), models(), lives(), prune()`.

`HE.mode`, `HE.setMode('edit'|'preview')`. `HE.settings.get(key, fallback) / set(key, value) / remove(key) / keys()`
(localStorage, safe; `storageKey` is the one localStorage key that holds them all as JSON). `set` and `remove`
return whether the stored copy was written (false: storage full or unavailable; memory changes anyway).

`HE.keys.register(combo | combos[], fn, {inInputs, inModal})` — combos like `'mod+z'`, `'mod+shift+z'`, `'delete'`,
`'backspace'`, `'escape'`, `'enter'`, `'alt+up'`, `'mod+d'`. Handlers are skipped while the event target is an
input/textarea/contenteditable unless `inInputs`, and while a modal is open unless `inModal`. Return `false` to
decline. canvas.js forwards the iframe's keydown events to `HE.keys.handle(e)`. Already registered by core: undo
`mod+z`, redo `mod+shift+z`/`mod+y`.

`HE.util`: `esc, debounce, clamp, tag, label, snippet, isVoid, isInline, isTextEditable, fragment(html, doc),
camelToKebab, storage.get/set/remove, combo(e), isTypingTarget(t), bytes(n)`, plus:
- `canContain(parent, child)` / `canPlace(ref, 'before'|'after'|'append'|'prepend', child)` — false when the HTML
  parser would rewrite the placement on the next parse (block in `<p>`, row outside a table section, nested
  links/forms/buttons, also anywhere inside a moved subtree…) or list/table structure would break. Every drop, paste and move target must pass it.
- `keepsChild(dest, el)` — canContain() plus the deeper parser checks (a block anywhere inside a `<p>`);
  `acceptsDrop(el)` — the user may move elements inside `el` (not media/form controls; a text block only while
  it is an empty box). Layer drags and level changes use both.
- `hasScript(root)` — the subtree carries a JS `<script>`, an `on*` attribute, a script URL (`isScriptUrl`),
  `srcdoc`, `<object>`/`<embed>`, `<base href>`, a `<meta http-equiv="refresh">` to a script URL…
  (`<template>` content included: declarative shadow roots go live in the canvas). This is new inline script,
  which needs the user's consent. Embedded external pages (`<iframe src="https://…">`, links, forms and refreshes
  to other sites) deliberately are not (`<object>`/`<embed>` are, whatever their URL). They inherit the sandbox of
  the frame they are in: they run script only in the run frame, that is in preview while the document's own
  scripts are allowed; in the edit frame (edit mode, a script-free or not-yet-allowed document) theirs do not run.
- `isScriptUrl(tagOrEl, attr, value)` — `javascript:`/`vbscript:` in any URL attribute (also after leading
  control characters, and as any item of an SVG animation's `;` list), or a `data:` document (text/html,
  application/xhtml+xml, image/svg+xml, text/xml, text/xsl, application/xml, any `+xml`; parameters and
  `;base64` allowed, any case) that a frame loads (`src` on iframe/frame), a link opens (`href` on a/area, SVG
  `<use>`), a form submits to (`action`, `formaction`) or an SVG animation sets (any item of `to`, `from`,
  `values`, `by`, on any element: SMIL can animate an `<a>`'s href). Not a `data:` image in `<img>`, not
  `data:,`. The scanner, paste cleaning (contextmenu.js) and the AI's checks all use it.
- `scriptBits(root)` — a Set with one fingerprint per piece of script; equal script gives equal strings
- `stripScript(root, keep)` — removes from `root`'s descendants every piece of script whose fingerprint is not in
  `keep` (a `scriptBits` Set): the element for `<script>`, `<object>`/`<embed>`, `<base>`, raw-text and noscript
  pieces and a refresh `<meta>` to a script URL; the attribute for `on*`, `srcdoc` and script URLs. Returns the
  count. All three share one scanner, so whatever `hasScript` reports, `stripScript` can remove.
- `intoHead(html, tags)` — `html` with `tags` put first in its `<head>` (one is made when the source has none);
  the doctype and comments before `<html>` are skipped, so a license header that mentions `<head>` is left alone.
  The edit frame, the run frame and 在新分頁預覽 use it.
- `isRawText(el)`, `rawSafe(el, text)` — raw-text elements and their escaped text
- `renameClashingIds(roots, write(el, attrs))` — free HTML ids for copied content.

`HE.ui`: `h(tag, cls, html)`, `icon(name, size)` (see `iconNames()`; inline SVG string), `toast(msg, {type, action:{label, fn}, timeout, sticky}) → {close}`,
`status(msg)`, `modal({title, body: Node|html, actions:[{label, kind, onClick(close)→false keeps open}], width, onClose}) → {el, body, close}`,
`confirm(msg, {okLabel, danger}) → Promise<bool>`, `prompt(msg, {value, multiline}) → Promise<string|null>`,
`menu(items, {x, y}) → {close}` (items: `{label, icon, shortcut, disabled, danger, checked, onClick, children}`,
`{separator:true}`, `{heading:'…'}`), `closeMenus()`, `menuOpen()`, `kbd(combo)`, `showTab(group, name)`, `currentTab(group)`.
Choosing a menu item or Esc gives focus back to what had it when the menu opened, before the item's `onClick`
runs (so a dialog it opens returns focus there too). A modal is labelled by its title (`aria-labelledby`; a confirm
is also described by its text); without a primary action (a danger confirm) focus starts on the ghost button (取消).
**Never use `alert`, `confirm`, `prompt` or `window.open`** (blocked in the Artifact).

## Interface language

This document quotes interface texts as they are written in the code, in Traditional Chinese, so that a search of
the sources finds them; `src/js/lang-en.js` gives the English of each.

Interface text is written in the code in Traditional Chinese. `HE.t(text, vars)` returns it as written, or its
translation when `HE.lang` is `'en'` (`src/js/lang-en.js`) or `'zh-CN'` (`src/js/lang-zh-cn.js`, which is not a
character-by-character conversion: it uses mainland terms, so 檔案 is 文件, 文件 is 文档, a table's 列 is 行). Rules:

- Every text the user reads goes through `HE.t('…')`, with the whole sentence as one literal. Never join pieces
  of a sentence with `+`: word order differs between languages. Put what varies in `{names}`:
  `t('符合 {n} 個元素', { n })`.
- `HE.t` returns plain text. Escape it (`util.esc`) where it goes into an HTML string, as any other text.
- A text with no translation is shown in Chinese and named in `HE.i18n.missing`.
- The language is fixed when the page loads: `HE.settings` key `ui.lang`, else the browser's language (Traditional
  Chinese for `zh-TW`, `zh-HK`, `zh-MO` and `zh-Hant`, Simplified for any other `zh`, English otherwise). `HE.i18n.set(lang)` stores the choice and reloads the page. Modules build their
  interface once and need not react to a change.
- Text in `src/index.html` stays Chinese in the markup; `HE.i18n.applyStatic` translates it when the editor starts.
- One Chinese text that needs two English ones takes a context: `t('位置', null, 'source')` reads the entry
  `'位置|source'`, and the entry `'位置'` when there is none.
- What the editor writes into a page as a first text (the sample text of an inserted block, a new slide) follows
  the interface language and goes through `HE.t` too.
- Every entry of `lang-en.js` has an entry in each other language file; the check fails when one is missing.
- CSS that the editor writes into a document carries a note in the document's language (`lang` attribute:
  Simplified Chinese for `zh-Hans`, `zh-CN` and `zh-SG`, Traditional for any other `zh` or none, else English), not
  the interface's, so that one document gets the same CSS from every editor.
- Not interface text, and left as it is: the templates (`samples.js`, `samples-en.js`), default file names, CSS comments written
  into the document, and everything sent to the AI model (already English). A line that keeps Chinese outside
  `HE.t` for such a reason ends with `// i18n-ok: <reason>`.
- A module that already has local variables named `t` calls `HE.t(...)` instead of taking `const t = HE.t`.
- `node tools/i18n-check.mjs` checks the files listed in its `DONE` (every module but `samples.js`): every `t()`
  text has an entry, no Chinese literal is left outside `t()`, no entry is unused, and the `{names}` of both sides
  agree. A new module goes into `DONE`. It also reads the five files of `ingest/src` the editor shares
  (`decimal`, `rules-core`, `chart`, `workbook`, `yaml-lite`) for the error codes they throw: each must have a
  line in `src/js/ingest-text.js`, no line there may name a code nobody throws, and each line's text must have
  its translations (see "Sources: charts and reconciliation rules").

## Styling rules

Use tokens from base.css only (`var(--panel)`, `--text-2`, `--accent`, `--sel`, …) — no literal colors except
inside the canvas overlay where `--sel` is used. On inverse surfaces (toasts, whose background is `--text`) use
`--ok-inverse` instead of `--ok`. On a `--danger` fill (error toasts, `.btn.danger`) text and icons use
`--on-danger` (white in light, near-black in dark: both at least 4.5:1). So does the focus ring of controls inside
an error toast (`.toast.error :focus-visible`). A `.btn.danger` keeps the accent focus ring, because that ring is
drawn outside the button, on the panel. Reuse base classes: `.btn` (`.primary .ghost .danger .icon .sm`,
`aria-pressed="true"`), `.seg`, `.input .select .textarea .mono`, `input.color`, `.field` (label + control
grid), `.field-stack`, `.row .grow .grid2 .grid3 .grid4`, `details.section > summary + .section-body`, `.chip`,
`.muted .mono .kbd .empty .tag-pill .divider`, `.pane-pad`. Module CSS goes in `src/css/<module>.css`, prefixed
by a module class to avoid collisions. Every form control gets a stable `id`. Must work at 360px wide
(panels become drawers below 900px — handled by base.css). Respect `prefers-reduced-motion`.
Icons: only `HE.ui.icon(name)`; no emoji in UI.

## Product behaviours everyone should know

- Edit mode (default): page links/forms don't fire; page scripts don't run (except in compat mode); click selects;
  dblclick edits text. Preview mode: the page behaves normally (scripts if allowed, links within the page), no
  overlay. Toggle in `#toolbar-view`.
- **Built-in templates (`HE.samples`)** are self-contained pages (one `<style>`, inline SVG, local fonts,
  fictional content) that double as test material. Each has a `lang`: `zh-Hant` in `samples.js`, `en` in
  `samples-en.js` (added with `HE.samples.add`; written for readers anywhere, not translated from the Chinese
  ones; their effects were written by the editor's own `HE.fx.apply`, and `en-traceable` is the output of
  `tactile-ingest fill` on `ingest/examples/traceable/`, to be made again there and never edited by hand), and
  `zh-Hans` in `samples-zh-hans.js` (written for readers in mainland China; no real brand or platform, no map,
  no absolute advertising claims, and IDs, account and filing numbers that are all zeros). `samples-site.js` adds one more in each of the three languages (`site`, `en-site`, `hans-site`): a multi-page site with a floating island, whose `pages` and `island` styles were written by `HE.pages.sync()` and `HE.island.sync()`. **`tools/resync-templates.mjs`** keeps them so: it opens every template that holds `[data-tpg]` or `[data-tfi]` in `dist/tactile.html` (headless Chromium), runs the two syncs and, when the document changed, writes the serialized document back over the template literal in `src/js/samples*.js` (backslashes, backticks and `${` escaped), then builds again; `--check` writes nothing and exits with 1 when a template is out of step. Run `node build.mjs && node tools/resync-templates.mjs` after every change to the CSS or the markup that `pages.js` or `island.js` generate; `tests/templates.spec.js` fails until then (it runs the two syncs on every template and expects no change). The 新增 menu lists the templates of `HE.i18n.docLangs` first and the others under 其他語言的範本; a first
  visit opens `sample` or `en-report` by the same rule. Every template must pass `tests/templates.spec.js`:
  listed in 新增 with its own icon and file name; no design-check warning or error and no sideways scroll on
  desktop, tablet and phone; the same HTML after export and reopening. The screenshot check's capture must also
  match the canvas for each. A new template needs an entry in `samples.js` `list`, a file name in fileio's
  `TEMPLATE_NAMES` and an icon in `TEMPLATE_ICONS`. Only `slides` may still have overflow, contrast and small-text
  issues: its 16:9 boards are wider than a tablet or phone.
- **Page scripts and trust.** Page scripts never get the editor's origin (its storage and AI keys, `window.HE`,
  the Artifact's `window.claude`) unless the user turns on compat mode.
  - **Edit frame** (`HE.canvas.frame`, the live doc): sandbox `allow-same-origin` only. The editor needs its DOM,
    so the page's scripts never run there.
  - **Run frame** (`HE.canvas.runFrame`): in preview, when the document has scripts and they are allowed
    (`canvas.scripts` preference on **and** `HE.doc.trusted`), the canvas shows `.cv-run`. It is an iframe with
    `sandbox=HE.PAGE_SANDBOX` (an opaque origin) and `referrerpolicy="no-referrer"`, the same in the Artifact,
    and the page it shows is `HE.doc.serialize()` with the additions below. The edit frame stays laid out
    underneath (`.cv-frame-box.is-running` hides it), so layout reads keep working.
    - **A nested srcdoc wrapper.** The run frame's `srcdoc` is a fixed wrapper document (`runWrapper` in
      canvas.js): `<base href="about:srcdoc">`, a rule that makes its one iframe fill it, and that iframe, again
      with `sandbox=HE.PAGE_SANDBOX` (a nested frame's flags can only add to its parent's) and
      `referrerpolicy="no-referrer"`, whose `srcdoc` is the page (attribute-escaped: `&` and `"`). Why: an
      about:srcdoc page falls back to its parent's base URL. Shown directly in the run frame, a page that removes
      its own `<base>` gets the editor's URL as `document.baseURI` (on disk the user's folders and name); in the
      wrapper it gets the wrapper's `about:srcdoc`, which it cannot reach (`location.href` is `about:srcdoc` too,
      and `document.referrer` is empty). A `blob:` page has no such fallback, but Chrome refuses fragment
      navigation to a blob URL from an opaque origin, which breaks every `#id` link and `location.hash` change;
      in the wrapper, `#id` links resolve against `about:srcdoc` and stay in the page. srcdoc always parses in
      standards mode, so the page renders like the canvas (the export keeps the document's doctype). Relative
      URLs resolve against `about:srcdoc` and fail, as in every earlier form of the run frame (the edit frame
      resolves them against the editor's address); a page with its own `<base href>` keeps it.
    - The editor's additions, never in the model or an export: the wrapper, and in the page the drag guard
      (below) first in `<head>`, off desktop the no-scrollbar rule, and while layers are hidden in the editor
      `data-he-hidden` on them (`serialize({mark})`) with the layers' own rule (`HE.layers.hiddenCSS`), so they
      stay hidden here too. The page gets no `<base>`. Hiding or showing a layer rebuilds the frame, which
      reruns the page's load-time scripts like any change.
    - It is rebuilt from the model 300 ms after a model change and when the device's scrollbar rule changes.
    - **Size at load (Chrome).** The page's frame runs out of process, and Chrome gives it its size a moment after
      it starts: in about a third of rebuilds (measured, headless Chrome 156) the page reads `innerWidth` and
      `innerHeight` as 0 while it parses, at `DOMContentLoaded` and at `load`, then gets a `resize` with the real
      size within 100 ms. A page that sizes itself only at load lays out at 0×0 until then; it should also
      listen for `resize`. The single srcdoc and blob: frames of earlier rounds showed it as often or more, and
      sizing the wrapper's iframe in advance does not change it.
    - **Self-navigation.** The run frame's own `load` fires once: the page's navigations (a reload, a form post,
      a link out) load only the wrapper's iframe. The wrapper's one script, an inline `onload` on that iframe
      (`RUN_NAV_ONLOAD`), counts its loads and from the second one posts `{tactile: 'run-nav'}` to the editor
      (the page cannot report its own navigations: a message posted from its `pagehide` arrives with no
      source). It comes from the run frame's wrapper, or from the pending frame's: a page that navigates in its
      load handler holds back the wrapper's own `load`, so the frame is still pending. `run-nav` rebuilds the
      frame with a toast, at most 4 times in 5 s. Past that the page is stopped: the run frame and any pending
      one are removed (left there, one would keep reloading, shown or out of sight, or stay where the page went),
      the canvas shows the document (the edit frame), the label reads 腳本已停止 (with the stop icon) and a toast
      says so once, with 重新整理畫布. What stops is the page of the frame that reported (each frame keeps the page
      it was built from): if the document has changed since (an edit still waiting on its rebuild, or a pending
      build of it), the changed page runs instead. It runs again when the page changes (a change that leaves the
      page as it was does not count, nor does a device switch), on the refresh button, on a mode switch or when
      the scripts state changes. The count holds across a stop and page changes, the navigations of the last 5 s,
      so a changed page that keeps navigating stops at its next one; the refresh button, a mode switch and the
      scripts state start a fresh count. A second `load` of the run frame itself (the wrapper reloaded; the page
      cannot navigate it) counts the same way.
    - **Messages.** The editor listens for `message` on its window and accepts only `{tactile: <kind>}` with
      that one key: `run-nav` only from the `contentWindow` of the run frame or of the pending one (the wrapper,
      as which a page cannot post); the guard's `run-filedrag` and `run-drop` only from the page's window,
      `contentWindow.frames[0]` of the run frame or of the pending one (cross-origin indexed access is allowed;
      read in a try/catch). It never takes files or markup over this channel (a page can post the guard's
      messages; the most a forged one does is the shield for a moment or a status line).
    - Leaving preview, a load, losing trust or turning scripts off removes it.
    - Script-free documents keep the edit-frame preview (with link interception).
    - **File drags: the page first, then the editor.** The run frame is cross-origin, so the editor hears nothing
      of a drag over it. The guard (`RUN_GUARD`, a fixed inline script and the only script the editor adds to
      the page) listens one task after `load`, in the bubble phase on `window`, for `dragover` and `drop`, so the
      page's own handlers on elements and `document`, and its `window` handlers added up to the end of its load
      handlers (`onload`, `<body onload>`), decide first; `window` handlers added later (after async work) run
      after the guard, and their drags go to the editor. A drag that starts in the page (an image, a link,
      selected text) is the page's own and never raises the shield: the guard notes `dragstart` in the capture
      phase before any page listener, until `dragend` or the next `pointermove` (dragend is lost when its source
      node goes). A drag from outside carrying `Files` that the page did not take (`!defaultPrevented`) it
      cancels (the browser would load the file in place of the page) and reports to the editor
      (`parent.parent`): `{tactile: 'run-filedrag'}` at most every 200 ms, `{tactile: 'run-drop'}` for a drop.
      It sends no file data. `run-filedrag` raises `.cv-run-shield` over the frame for 900 ms, renewed by file
      drags over the shield, so the rest of the drag and the drop reach the editor's own handlers (open the
      file, insert images) as in edit mode; `run-drop` (dropped before the shield was up) says so in the status
      line; a drop or dragend hides the shield. A page drop zone that accepts the drag keeps it: no message, no
      shield. A drag that first crosses a part of the page that does not accept files raises the shield, which
      then also covers the page's drop zone for the rest of that drag. A CSP `<meta>` in the page does not block
      the guard (it comes first in `<head>`, and a meta policy applies only to what follows it); a page where
      the guard does not run gets no shield, and a file it does not take loads in its place, which the
      self-navigation rebuild undoes.
    - The toolbar shows 「腳本執行中・已隔離」 (`#cv-run-label`) while it is up (「請重新載入以恢復隔離」 in a tab
      that had compat mode on, see below).
    - It is rebuilt only when its page differs from the one it was built from (`S.runSrc`): each build reruns
      the page's load-time scripts, and one change can arrive twice (an undo that restores trust builds it on
      `doc:trusted`, then emits `doc:changed`). The refresh button, a self-navigation and a device change build
      directly.
    - Focus moves into it only on a rebuild while focus was already in the old run frame: the editor focuses the
      page's window (`frames[0].focus()`, which makes the run frame the editor's `document.activeElement`), or
      the run frame itself when that fails. Entering preview leaves focus in the editor, so Alt+P and the other
      shortcuts keep working; keys typed in the run frame never reach the editor (the label and preview button
      titles say so, and the status line once per session).
  - **Compat mode** (「編輯時也執行（相容模式）」 in the 腳本 menu; not offered in the Artifact): the edit frame
    gets `allow-same-origin` + `HE.PAGE_SANDBOX`, which is the old behaviour, and preview uses the edit frame.
    - Turning it on needs a danger confirm (refused while the AI runs; void if the document changed while the
      confirm was open), and it also allows the document's scripts.
    - It lives only in canvas memory, for the current document, and is never stored.
    - It ends on any `doc:loaded` (open, new, template, autosave restore), on `doc:replaced` (an undo or redo
      across 編輯整份 HTML included), when trust drops, and when scripts are turned off. Trust coming back (undo,
      consent) never turns it back on.
    - The consent covers the scripts it was confirmed over (`scriptBits` of the model then): an undo or redo that
      brings back any other (deleted before compat went on, or a state only allowed for preview) ends it with a
      status line. The restored edit frame is built without `allow-scripts`, and `live.safe()` keeps copies out
      of the scripted frame until it shows.
    - The `#cv-compat-off` chip shows while it is on.
    - It taints the tab until it reloads: the page ran in the editor's realm, and ending compat mode cannot undo
      what it did there (functions it handed to the editor's timers and listeners, objects it patched, what it
      stored). When compat ends for any reason, a sticky toast offers 重新載入 (also in the 腳本 menu), the run label
      no longer says 已隔離, and the trust confirm says the isolation is incomplete. The AI settings (`ai.*`, in
      memory and as stored) are copied when compat first goes on; if they differ when it ends, a toast and the
      腳本 menu offer to restore them. The restore compares again afterwards and says it worked only when nothing
      is left; otherwise a sticky error toast names what was not restored and why (storage full, or a page
      script still at work) and offers 重新載入, and the menu keeps the item. On `pagehide` the changed key names (never values) go to sessionStorage
      `tactile:compat-ai`, reported once after the reload. This is best effort: code already running in the
      editor's realm can change anything the editor shows.
  - **Trust.** Built-in templates load trusted. Opened, pasted and dropped files (and autosaves of them) load
    untrusted. Their scripts run only after the user allows them behind a confirm: 「允許執行…」 in the notice
    toast (once per load, when the preference is on), or 「在預覽中執行腳本」 in the 腳本 menu.
    - An autosave's `trusted` flag can only bring back the run frame, never compat mode.
    - New script (paste, AI writes, a new handler attribute or script URL, a `data:` page in a frame or link, a
      refresh `<meta>` to one, 編輯整份 HTML) makes a trusted document untrusted again; copies of script the page
      already has do not. An external page embedded or linked (`https://…`) is not script (see `util.hasScript`).
    - Script that would reach the model from the live frame (typed text, Enter splits) is stripped by
      `HE.live.clean` instead. When the edit frame runs no page script, `commitLiveContent` strips the live element
      itself (so the canvas keeps matching the model); a scripted frame (compat mode) keeps what the page did.
    - Changes landing inside a `<noscript>` are checked in place too: the model parses it as markup and a
      scripted frame as raw text, so a comment or `<style>` holding `</noscript>` there would end it early.
  - `HE.canvas.setScripts(on)` and `setCompat(on)` are async (they may confirm). 在新分頁預覽 renders the page
    inside an iframe with `HE.PAGE_SANDBOX` + `allow-downloads`; it always runs the scripts (isolated), whatever
    the trust state, so the consent does not mention it.
  - The isolation covers the editor's preview only. An export keeps every script and is an ordinary page when
    opened; from disk in Chromium it shares localStorage with a `file://` editor (the settings; not the AI keys
    and not the autosaved documents, which from disk are in each tab's sessionStorage). The trust
    confirm says so, and an export of a scripted page from a `file://` editor with stored AI keys toasts it once.
- Selection can be multiple (shift-click); ops take arrays.
- Keyboard: Delete/Backspace remove, mod+D duplicate, mod+C/X/V copy/cut/paste elements, Esc select parent,
  Enter start editing text, alt+↑/↓ move among siblings, mod+Z/mod+shift+Z undo/redo, mod+S save (export where
  files cannot be written), mod+shift+S save as (File System Access only), mod+O open, mod+K focus AI prompt.
- **Files on disk (fileio).** Where the File System Access API works (`fsaAvailable()`: Chromium, top-level page,
  not the Artifact), the main file button is 儲存 and documents can stay linked to a file (`state.file`).
  - A link comes only from a load that passes one in: `openText(html, name, {file})`, from the open picker or a
    drop (`getAsFileSystemHandle`, asked for during the drop event; a drop on the canvas arrives through the edit
    frame, so its handle is `structuredClone`d into the editor's window before that frame re-renders and takes
    the handle with it). Every other `doc:loaded` (template, paste, the input fallback, autosave restore)
    unlinks. Linked or not, opened files load untrusted.
  - `save()` = save back when linked, save as otherwise (download without the API). Save back asks for write
    permission (needs the user's gesture), rereads the file and compares `{lastModified, size}`, then a content
    signature: changed on disk and dirty here → conflict dialog (覆寫 / 載入磁碟版本 / 另存新檔 / 取消); changed
    and clean → load it instead. Clean on both sides → nothing is written (a write would only reformat). What is
    written is UTF-8 with the file's own line endings, and a BOM when the file has one (as it is on disk now: a
    BOM added or dropped elsewhere with the text unchanged is taken over) or a converted legacy file declares no
    charset. A file whose encoding was only guessed (no BOM, no declaration, not UTF-8: `link.guessed`) asks once
    before the first write (存回前確認文字編碼: 取消 / 另存新檔 / 仍要存回), since a wrong guess rewrites every
    non-ASCII character for good. Before deciding anything, saving (and export, copy, the disk reload) commits what
    is being typed: an in-place text edit, a focused inspector field and page CSS still on its debounce
    (`HE.inspector.flush()`; leaving the page does the same, for the autosave). After a write the stamp is
    cleared, so the next check reads the file back.
  - "Dirty" against a linked file means "differs from the file": download and copy do not clear it (markExported
    leaves dirty and the baseline alone while linked); only a write or a load from disk does. Save and the disk
    reload refuse during an AI run or any open history transaction.
  - `checkDisk()` runs every 2 s while the tab is visible and on focus. During an AI run or another open history
    transaction it does not read the file at all (the run's changes do not count as edits yet); the next check
    after it decides. A change made elsewhere reloads a clean document with `HE.ops.replaceDocument` (one undo
    step, label 載入磁碟上的版本), but only while nothing else is under way: with a modal open, text being
    edited, a pointer drag, or a focused field while the window has focus, the reload waits and the status says a
    newer version waits. A dirty document gets a sticky offer. A file that is gone (NotFoundError) withdraws the
    offer and shows 找不到原檔.
  - The link survives reloads: IndexedDB `tactile` / `handles`, keyed by the autosave tab id, and the autosave
    record carries `file: true` plus `fileSig`, the disk version its text is in step with. A restore relinks it;
    when the link's own sig has moved on (a save the record missed), the disk version counts as foreign. Reading
    again may need the user's OK (`queryPermission`): until then nothing is watched, the status says
    需要再次允許存取, and a document with unsaved edits keeps its 允許存取 toast up (`accessGranted` closes it,
    from the poll, a save or the toast). Entries whose record is gone are pruned at boot. Not on
    `file:` (`linkPersistable()`): every page opened from disk shares that origin's storage, so there the link
    lasts as long as the tab. In compat mode page scripts share the origin and can reach these handles, like
    everything else the editor stores.
- **匯出 PDF 與 PNG (fileio + HE.snap).** Both work on a clean copy: `HE.doc.serialize()` loaded as `srcdoc` into an
  off-screen iframe (`.fio-copy-frame`, in the editor document, removed afterwards). So neither holds `data-he-id`,
  `#__he_editor_css`, a selection outline or any editor state; layers hidden in the editor are in both, as in the
  HTML export; and page scripts do not run, so both show what the edit frame shows. The copy's additions are never
  in the model or an export.
  - **PNG.** The copy's frame has `sandbox="allow-same-origin"` and the size of the edit frame's viewport (the
    current device), with the page scrollbar hidden so the widths match. `HE.snap.page(doc)` draws its full height
    from the top with the capture's own code (`render`: the same inlining, stand-ins and viewport-high slices; the
    two-screen limit is `regionFor`'s, for the AI, not the drawing's). Scale: 2 device pixels per CSS pixel; 1 when
    that would pass 16384 px a side or 48 million pixels; below 1 (a whole number of pixels per slice) when 1 does
    too, with a toast. Leaves as `<name>.png` through `<a download>`, or in the Artifact through

- **Effects (HE.fx).** Hover, entrance and scroll effects are platform CSS only (no page script, so the trust
  model is untouched and they work with scripts off). The document stores:
  - classes `tfx-h-<name>` / `tfx-e-<name>` / `tfx-s-<name>`, at most one per kind and element;
  - inline custom properties `--tfx-k` (intensity), `--tfx-t` (timing -1/0/1) and `--tfx-color`, plus
    `--tfx-i` / `--tfx-n` on the children of fan and deal containers;

    for a bar anchored at the right (top) edge, on the bars inside a grow container (`tfx-e-grow`). They are found
    when grow is applied (or found again from its hint), measured with `fx-motion` and ▶ 預覽 switched off for the
    moment. A bar is a filled box (a colour or a gradient, not a picture), empty or holding a short value (as text
    or in unfilled inline labels), anchored at one edge of its line (a centred box is not a bar) and at least 4px
    thick, that: has a plain percentage width/height under 100% in its own style (a flex basis only without
    flex-grow; thin bars on their own, thicker ones when two or more on that axis differ); or tiles a thin track
    from one edge with no gaps (one fill or stacked segments; a lone square box only in a filled track); or sits
    beside a bar like it (same thickness and edge: the 100% bar, bars sized by classes); or is one of a row of two
    or more equally thick boxes of different lengths on a common edge (columns). Without a laid-out canvas only the
    inline percentages count, and a marked box that cannot be measured but still looks like a bar keeps its
    marker. sync drops markers no grow container holds; grow asked for on a bar goes to the element around it
    (replacing that element's entrance, which the notes say);
  - the head styles `fx` (structure, `@property`) and `fx-motion` (everything that moves, inside
    `prefers-reduced-motion: no-preference`; entrance/scroll inside `@media screen` + `@supports (animation-timeline: view())`).

  history closer, so a paste, duplicate, AI edit or source edit that adds or removes `tfx-*` classes gets its CSS in
  the same undo step. Change effects only through `HE.fx.apply/remove/removeAll` (or `setClasses`, which sync
  follows); never hand-edit the `fx`/`fx-motion` styles. sync also removes copies of them outside the head (pasted
  page source), and pasting page source as text leaves them out.

  integer `--tfx-in` from 0 to 1 (halfway through its range, which 早/中/晚 moves), and its bars follow with
  `@container style(--tfx-in: 0)` (`scale: 0 1`, or `1 0` upright) and `style(--tfx-in: 1)` (a 0.9 s time-based
  animation from zero), so a bar is never left at a wrong length when the scroll stops. The growth sets
  `transform-origin` only inside its keyframes and fills backwards, so a grown bar's own scale, transform and origin
  apply as authored. `--tfx-in` is registered with initial value 1: without scroll timelines, style queries or with
  reduced motion the bars stay as authored. A container already past the trigger on load plays at once. A grow
  container that is a child of a deal container gets one rule with both animations. Grow has no intensity.

  and the overlay reads author values; the model never sees that attribute. The inspector's ▶ 預覽 replays
  effects with an editor-only `<style data-he-editor="fx-demo">` and the live-only `data-he-fx-demo` attribute.

- **Multi-page documents (HE.pages).** One HTML file can hold several pages that a navigation bar switches between. The
  switching is CSS only (`:target` and `:has()`): no page script, so it works with scripts off, in preview, in an
  exported file and with the browser's back button and a link to `file.html#news`. The document stores:

    has a unique `id`, its address (made from its name's letters and digits, `news`, `news-2`; a name with none, such
    as a Chinese one, gets `page-4`), and `data-tpg-title`, the name the pane and the links show. Renaming a page
    never changes its `id`.

    none. Each holds one `<a href="#id">` per page (inside an `<li>` when the bar is a list). Everything else in a

    link), the links of pages in the pages' order (they trade places among themselves), and the style. Links to a
    page that existed at the last sync and is gone are removed, however it went: the pane, the Delete key, the
    layers panel, the AI, the last page or the container itself (the document then has no pages and no `pages`
    style, and the bars keep only the user's own links). After the whole document was swapped (編輯整份 HTML, the
    AI's `replace_document`; `doc:replaced`) the pages seen before are still compared, but there a link goes only
    when no element has its `id` any more. It runs as a history closer and after each tool of

    duplicate the user placed before the run is never removed, and outside a run no duplicate is. The tool whose
    call wrote the duplicate gets `page_links` in its result (the count, and that the editor maintains the links). Never hand-edit the `pages` style. A document

    dark for a `color-scheme: dark` root); element opacity included. Text over a picture is listed in
    `not_checked`; disabled and `aria-hidden` text is skipped.
  - `small_text`: under 12px (not `<sup>`/`<sub>`). `hierarchy`: headings smaller than or indistinguishable
    from the body text (the character-weighted most common non-heading size), a lower level larger than a higher
    one, skipped levels, more than 8 sizes, a size 1px off a much more common one, more than 3 families. A
    heading's size is that of its own text; only a heading with no text of its own takes the size of the text
    inside it with the most characters (so `前菜 <small>APPETIZERS</small>` is measured at 前菜's size).
  - `overflow`: content past the page edge (the topmost box with content, outside any box that clips or scrolls;
    siblings past by the same amount are one issue), and text cut off by a box with `overflow: hidden/clip`
    (ellipsis and line-clamp are intended). Text inside a box that scrolls can be scrolled into view, so a box
    farther out counts only what it cuts off of that scroller (a `<pre>` that scrolls inside a rounded frame
    with `overflow: hidden` is fine; a scroller wider than the frame that clips it is not). `overlap`: line boxes of text from unrelated elements intersecting (not between text inside a `position: fixed` or `sticky` box and text outside one: where those meet depends on the scroll position)
    (text measured by its line box, not its glyph area, so tight line-heights do not count; faint text skipped).
  - `spacing`: a vertical margin, padding or gap value 1px off a much more common one (≥ 8px), and uneven
    gaps between three or more same-tag, same-class siblings stacked in one column or row.
  Not walked: closed `<details>` content, `content-visibility: hidden`, `display: none` (layers hidden in the
  editor are listed in `not_checked`), SVG and form field text. Limits: 6000 elements, 3000 text elements.
  The AI tool `check_design` (read-only, `ids` and `checks` optional) returns it as is; plan mode gets it in
  the context. The system prompt asks the agent to run it after visual changes and to fix only what its own
  change broke.
- **Screenshot check (HE.snap + ai).** `HE.snap.capture()` draws the live edit frame without screen sharing or any
  permission: it clones the document, inlines stylesheets (`cssRules`, else `fetch`), `@import`, images and
  fonts as `data:` URLs (font faces whose `unicode-range` misses every character of the page are dropped; 16 MB
  fetched per capture, a cache across captures), turns `iframe`/`video`/`canvas`/`object`/`embed` into an
  `<img>` of what they show (same-origin frames are drawn in turn) or a labelled gray box, pins each stand-in to
  the computed box of what it replaces, strips attribute names XML rejects, adds
  `animation:none; transition:none` (effects at rest), and draws the clone through SVG `<foreignObject>` onto a
  canvas. Inside an SVG image `vw`, `vh` and media queries resolve against the outer `<svg>`, so every draw is
  one viewport (`clientWidth` x `clientHeight`) with the page shifted under it, and taller areas are stitched
  from viewport-high slices; fixed elements sit where they are at scroll 0. The area (`regionFor`) is the full
  width around the given elements plus 32px, one to two viewports high (`cut` when the elements go on below);
  `<html>`/`<body>` alone or no ids: what is on screen. Output is a JPEG scaled to `maxEdge` (the AI uses 1568).
  `missing` lists what became gray boxes (images that neither `fetch` nor a same-origin draw can read, outside
  frames, unreadable video or canvas). `probe()` is false where the browser taints such drawings; then the
  toggle stays hidden. Measured in Chromium against real frame screenshots: 0.2-3.2% of pixels differ
  (anti-aliasing), 2-93 ms for a whole template page. Not verified in Firefox or Safari.
  The AI pane's「修改後看畫面」checkbox (setting `ai.look`, off by default) is shown when the provider can take
  an image: the API providers always (an OpenAI-compatible model without vision fails that step with a note);
  the Artifact only where `sample.limits()` reports `images` and `tools`, which needs the Artifact published

  holding the image (`image` block / `image_url` data URL) and the instructions; the Artifact makes a second
  `sample()` call with `images: [blob]` and the request in the context. The reply ("OK" means nothing to fix)
  shows in its own 看過畫面 block; a failed check is a note, never an error, and keeps the run's edits. It runs
  at most once per request. History trimming counts a stored image as 6000 bytes (about its token cost).
  Tried once in a real claude.ai Artifact (2026-11-07, Chromium): the checkbox showed, the capture worked inside
  the sandbox and `sample()` took the JPEG.

- **Sources: charts and reconciliation rules (HE.ingestCore + HE.fill + HE.prov + ai).** The format is `docs/spec/provenance.md`; the
  command-line tool is `ingest/`. What both sides must compute alike is written once, in `ingest/src/decimal.mjs`,
  `rules-core.mjs` and `chart.mjs`. `build.mjs` turns them, and `yaml-lite.mjs`, into `src/js/ingest-core.js`: each
  module in a function of its own, `import { … } from './x.mjs'` read from the modules before it, the exports put
  together on `HE.ingestCore = {dec, format, readShow, shownText, SpecError, …, readRules(doc),
  expandRules(rules, factsMap), runRule(item, facts), expandRef, readChart(get, facts), drawChart(chart, lang),
  chartIds(chart), reportLang, parseYamlLite(text)}`. The build fails when one of the four imports anything else,
  renames an import, exports in another form, or two of them export the same name.
  - **Reading rules.yaml.** The yaml package does not fit in one offline file, so the editor reads a rules file
    with `ingest/src/yaml-lite.mjs` (`parseYamlLite`, which imports only `SpecError`). tactile-ingest does not use
    it: `parseRules(text)` in `ingest/src/rules.mjs` keeps the yaml package. The reader takes a subset: block
    mappings; block sequences of scalars, mappings or sequences; plain, single- and double-quoted scalars on one
    line; decimal numbers, `true`/`false`/`null`/`~`; flow sequences of scalars on one line; `#` comments, blank
    lines, one leading `---`, a byte order mark, CRLF. Plain scalars are typed by the YAML 1.2 core schema
    (`007` is 7, `2026-11-10` and `yes` are text). Everything else throws `SpecError` with the line and the
    construct: anchors, aliases, tags, block scalars, flow mappings, a second document, directives, tabs,
    duplicate keys, complex and merge keys, scalars that go on over lines, keys that are not strings, hexadecimal,
    octal, `.inf`, `.nan`. **For every text it accepts it must return what the yaml package's `parse` returns**:
    `ingest/test/yaml-lite.test.mjs` compares the two on the example rules files, on hand-written cases and on
    60,000 generated texts. A construct added to the reader goes into that test first.
  - **Messages.** The errors of `decimal`, `rules-core`, `chart`, `yaml-lite` (`SpecError`) and of `workbook`
    (the `fail(message, code, vars)` its caller hands in) carry `message` (the Traditional Chinese text
    tactile-ingest prints, which must not change), `code` (`show.*`, `rules.*`, `chart.*`, `book.*`, `yaml.*`) and
    `vars`. In those files an error is made with `err('<code>', {vars}, message)`. The editor never shows
    `message` for a known code: `HE.ingestText(err)` (`src/js/ingest-text.js`) has one `t()` text per code, which
    says 來源檔或出處資料 where the tool says facts.json (the editor has none). An error without a code, or with
    one the table does not know, is shown as its message. `fill_problems` and the errors of `edit_rules` are these
    same texts, so they follow the interface language. A new error needs a code, a line in `ingest-text.js` and
    its translations; `tools/i18n-check.mjs` fails otherwise. The `why` of a rule that cannot be computed
    (`runRule`) is not an error and has no code: the pane computes rules with `HE.prov.runRule`, which is worded
    through `t()`.
  - **Charts.** `HE.fill.run()` draws every `[data-chart]` element that is not inside another: the attributes of
    spec 9.1, the facts from `HE.sources` and then from the block the document carries, the language from
    `<html lang>`. The drawing is the text `tactile-ingest fill` writes (`tests/charts-rules.spec.js` compares the
    two with ingest's `holdsDrawing`) and goes in with `HE.ops.setInnerHTML`. An element that already holds that
    drawing is left alone (no write, no undo step); an earlier drawing (`svg[data-chart-drawn]`) is replaced; an
    element that holds anything else, has `data-fact`, or whose attributes `readChart` refuses is named in
    `problems` by its data-he-id and stays as it is. `chartIds` go into the block's `facts`.
    `run() → {filled, charts, problems, facts}`; `filled` and `charts` count what was written this time.
    `HE.fill.refill()` is `run()` on the user's word, as one undo step named 重新填入: it returns the same and
    `changed`, and records no step when nothing was written. The pane's 重新填入 button (`HE.prov.refill()`)
    shows when the document has a `[data-fact]`, a `[data-chart]` or a block; it says in the status line how many
    numbers and charts were written and how many problems there are, and lists the problems in the pane until the
    next refill or the next document. It is for citations and charts written by hand, and for a newer copy of a
    source file dropped in under the same name (nothing is refilled by the drop itself).
  - **Rules.** They live in the block: `rules: {sha256, approvedBy?, approvedOn?, items}`, items expanded as
    `tactile-ingest fill` writes them. For rules made in the editor, `fill.js` `rulesYaml()` writes the
    items as one canonical text (parts as a list of IDs, every string in JSON double quotes, `\n` line ends) and
    `sha256` is the SHA-256 of that text, worked out (async, `crypto.subtle`) before the write. So the file from
    下載 rules.yaml passes `tactile-ingest verify --rules`.
    `HE.fill.loadRules(text) → Promise<{rules: [result]} | {error}>` takes a rules.yaml the user wrote in place
    of the rules there are: `parseYamlLite` → `readRules` → `expandRules` against the facts of the loaded files
    and of the block, then one undo step (載入 rules.yaml) that writes `{sha256, approvedBy?, approvedOn?, items}`
    with `sha256` the SHA-256 of the file's bytes and the approval as the file states it: the block
    `tactile-ingest fill --rules <file>` writes, so `tactile-ingest verify --rules <file>` passes. A file that
    cannot be read, or that names a cell there is no fact for, writes nothing. The text stays in the tab's memory
    (never in the document): while the block's `rules.sha256` is that file's, `rulesFile()` returns the file as
    it was (`original: true`); after any change to the rules it returns the canonical text, as before.
    `HE.prov.loadRulesFile(file) → Promise<bool>` is the way in, from 載入 rules.yaml in the pane
    (`#prov-rules-input`) and from a `.yaml`/`.yml` file dropped on the window (`fileio.js`): at most 1 MB, UTF-8
    (decoded with `fatal`, the byte order mark kept so that the text hashes as the file), refused while the AI
    runs, and with rules already in the document the user is asked before they are replaced. **Loading rules is
    the user's act only: it must never become a tool of the AI**, because a file can carry an approval. `HE.fill.addRule(spec)`, `removeRule(id)` and
    `approveRules(name)` return `Promise<{rules: [result]} | {error}>`; each is one undo step through `HE.ops`
    (`run({rules})`), and the IDs a rule reads go into `facts`. `addRule` checks with `readRules` and expands with
    `expandRules`; a rule that fails either is not written. **Any change to the rules removes `approvedBy` and
    `approvedOn`**: the rules are then not the set a person approved (spec 8). `approveRules` writes the name and
    today's local date. `HE.fill.rules() → {items, approvedBy, approvedOn, results} | null`;
    `HE.fill.rulesFile() → Promise<{text, same, original?} | null>` (`same` is false for rules that
    tactile-ingest filled in from a file of its own that was not loaded here: the canonical text says the same
    but hashes differently until the rules change or are approved here).

    (or a name field and 確認規則), 下載 rules.yaml, 載入 rules.yaml and the form 新增規則 (kind, name, cell IDs,

    also shows for a document that has no block yet. Everything from a source file, a rule or a rules file is
    written with `textContent`.

    drop an .xlsx on the window; with one it has a search field (`HE.sources.search`, 20 results; each shows the
    cell's text, its address and its headings). A click on a result calls `HE.prov.cite(factId) → {id, where} |

    (`where: 'after'`); else into the selected element when it is a text element (`util.isTextEditable`, not a
    root, not in a chart) — at the caret (`'caret'`) when the user was typing in that element just before and its
    text has not changed since, otherwise after its text (`'end'`). The status line says which. A click in the

    shown (a factor on a text cell, a factor that is not a positive number) writes nothing and is said under the
    controls; otherwise one undo step sets `data-fact-scale` / `-digits` / `-group` and fills again. The controls
    are rebuilt only when the selected citation or its attributes change, and the results only when the query or
    the source files change, so an element under the pointer is not replaced during a click.

    always in a document with neither a source file nor a block. The system prompt says what to do with it (cite
